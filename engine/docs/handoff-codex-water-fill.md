# Handoff: lakes that fill the hollow they sit in (`water.fill`), a calmer wave spectrum, and the showcase

The owner looked at the showcase lake (2026-10-26) and said the water looks bad: `water.surface` is a closed square body, so the lake is a slab sticking out of the ground with a hard polygon edge, banded vertical side walls, no shoreline (no depth fade, no foam), and the surface is uniform fine noise with glints everywhere and no larger swell. River water (`river.carve` + `river.water`) already carries depth, wet banks and foam per vertex and looks right at the banks. This job gives lakes the same treatment.

## Part 1: `ve_world::river::fill_basin` (new file `crates/ve-world/src/river/lake.rs`, re-exported from `river`)
```rust
pub struct LakeProfile { pub level: f32, pub shore_width: f32 }   // water surface height in world metres; width of the wet bank in metres
pub fn fill_basin(ground: &GroundRef<'_>, seed: [f32; 2], profile: &LakeProfile, cancel: &dyn Fn() -> bool) -> Result<RiverOut, RiverError>
```
Flood fill (4- or 8-connected, deterministic order) from the cell under `seed` (world x, z; `origin` and `cell` as in `GroundRef`) through every cell whose ground height is below `level`; that connected set is the lake. Return the same `RiverOut` rivers produce (read `river/stream.rs`): `water_height` = `level` on lake cells and the ground height elsewhere, `channel_mask` = 1 on lake cells and 0 elsewhere, `bank_mask` = the wet bank: 1 at the cell next to the shore falling smoothly (linear or smoothstep) to 0 at `shore_width` metres from the nearest lake cell (distance by a two-pass chamfer or exact within the cell size; monotone in distance), 0 on lake cells or beyond; `flow_speed` and `flow_dir` all zero. Errors: `Cancelled` (poll `cancel` every few thousand cells), `BadParameter { name, .. }` with `name` containing "seed" (outside the grid, not finite, or its cell is not below `level`) or "level" (not finite, or no ground at all below it near the seed is covered by the same rule: say which), and `BadParameter` for a negative or non-finite `shore_width`. Water that reaches the grid border simply continues to the border (no error). `GroundRef::check()` as `carve_river` does. Documented, deterministic, no unwrap/expect/panic, files under 400 lines.

## Part 2: the node `water.fill@1`
Input: a `terrain.tile` result (a Poly with a height grid, as `river.water` takes the output of `river.carve`; read `crates/ve-modeling/src/world_river.rs` and the terrain tile data it uses). Parameters: `at` Vec2 (world x, z of the seed, default the tile centre), `level` Num (water surface height in metres, required or default 0), `shore` Num (shore width in metres, default 3, 0.1..50), and the same look parameters as `river.water`: `shallow`, `deep`, `clarity`, `ripple`, `foam`, `opacity`, `direction`, `seed`, with `flow` defaulting to 0 (a lake has no current; keep the parameter, range as river.water). Build the water mesh the way `river.water` builds its sheet from a `RiverOut` (reuse that meshing code, extracted into a shared function; do not duplicate it): a flat sheet at `level` over the lake cells plus a one-cell skirt so the edge is smooth, per-vertex colour `[flow x, flow z, depth, foam]` in the same encoding (flow 0.5, 0.5; depth from `level - ground` remapped by `clarity`; foam from the wet bank mask times `foam`), same material finish (`SurfaceWater`) so the existing water shading draws it. NO side walls, NO closed body. Errors become diagnostics that name `at` ("`at` is not in a basin below `level`") or `level`. Registered like the other world nodes, with ranges, defaults and docs (see how `river.water` is registered; the node spec file and `crates/ve-modeling/src/world_ops.rs`), and add it to the `world` guide topic in `tools/mcp/guide.mjs` with a short example (dig a hollow with `terrain.flatten`, fill it with `water.fill`), and mention in the `water.surface` description that on a landscape `water.fill` is the one to use.

## Part 3: a calmer, more natural wave spectrum (`crates/ve-render/src/water_waves.rs` and `shaders/water_waves.wgsl`)
Keep the public API and every test in `crates/ve-render/tests/water_waves.rs` passing. Change the table so the field has a visible larger swell instead of only fine noise: the longest waves carry most of the height (amplitude falls off faster toward short wavelengths, for example proportional to wavelength^1.3 before the slope limit), the shortest waves (below about 0.8 m) are weaker, so the result reads as swell plus a little ripple. The tests that constrain you: steepest slope at ripple 1 stays in 0.1..0.9, max height under 0.15 m, spread of wavelengths above 8x, directions within 70 degrees. In the fragment shader tone the sun glints down (they are everywhere in the screenshot): glints only where the wave normal tilts toward the sun beyond a threshold and scaled by the wave steepness, with a smooth falloff, so they sparkle on crests, not across the whole sheet. Do not add textures.
