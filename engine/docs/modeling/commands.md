# Typed command set (contract v1, draft for G1a)

Every edit, from chat, text, node graph, inspector, outliner, viewport gizmo or XR controller, is a
`CommandBatch`. The Rust engine owns the document; the editor and providers send batches and receive
results. JSON below is the canonical wire form (the TS types are generated from the Rust schema).

## Document
```json
{
  "schema": 1, "id": "d_7k2m9q4x", "revision": 12, "units": "m", "seed": 1,
  "nodes": [ { "id": "n_a1b2c3d4", "op": "profile.polygon@1", "label": "outer",
               "params": { "points": [[0,0],[0.06,0],[0.11,0.12],[0.07,0.26],[0.05,0.30],[0,0.30]] },
               "inputs": {}, "flags": { "muted": false, "bypass": false } } ],
  "outputs": [ { "name": "vase", "from": { "node": "n_f9e8d7c6", "port": "out" } } ],
  "ids": { "next": 5, "salt": 618720104 },
  "materials": [], "groups": [],
  "editor": { "positions": { "n_a1b2c3d4": [120, 80] }, "collapsed": [] }
}
```
- IDs are generated by the engine (`n_`, `m_`, `d_` plus 8 base32 characters) from the `ids.next`
  counter, which only moves forward: an ID is unique within the document, deterministic (the same
  commands give the same IDs) and never reused after deletion or undo. **Commands never supply IDs.**
  A batch refers to a node it adds by an alias (below). Group IDs (`g_`) arrive with G4.
- Links are always arrays per input port (`"inputs": { "in": [ { "node": "...", "port": "out" } ] }`).
- Values are stored in SI units (metres, radians). `OperatorSpec` declares display units and ranges.
- Operators are written `family.name@version`. A node pins its version; changing it is a command.
- The `editor` layer is saved and undoable but excluded from the evaluation hash. G1a has node
  positions and collapsed flags; frames and reroutes (and their commands) arrive with V2.

## Aliases
A node does not have an ID until the batch is applied, so a batch that adds nodes and links them uses
aliases: `{"add_node": {"op": "solid.revolve@1", "alias": "$body"}}`, then
`{"connect": {"from": {"node": "$outline", "port": "out"}, "to": {"node": "$body", "port": "in"}}}`.
An alias is `$` plus 1 to 32 characters from `[A-Za-z0-9_]`; it exists only inside its batch, must be
defined by an earlier command, and may be defined once. Anywhere a command takes a node, it accepts a
real ID or an alias.

## Batch
```json
{ "doc": "d_7k2m9q4x", "base_revision": 12, "transaction": "t_01HZ...", "label": "widen opening",
  "commands": [ { "set_param": { "node": "n_a1b2c3d4", "param": "points", "value": [[0,0],[0.06,0],[0.11,0.12],[0.09,0.26],[0.07,0.30],[0,0.30]] } } ] }
```
Rules: at most 10,000 commands and 4 MiB per batch (a text program costs one command per node, one per input link and one per output). The batch is atomic. Validation runs on a candidate
copy; the committed document changes only on success and a matching `base_revision`. The first
failing command stops the batch and its index is in the diagnostic (`command`). After a connect or a
version change the whole graph is re-checked (ports, arity, types, cycles), so every prefix of a
batch is a valid graph.
`transaction` is the idempotency key: a repeated key returns `already_applied` and applies nothing,
whatever the base revision. Only committed batches are remembered (a rejected or conflicting batch
may be retried with the same key). Undo and redo advance the revision and never rewind the ID
counter; the undone batch's key stays remembered, so re-sending it does nothing: use a new key.

## Commands
| Command | Fields | Notes |
|---|---|---|
| `add_node` | `op`, `params`, `label?`, `alias?` | Missing params take spec defaults; required ones must be present; unknown fields are refused |
| `remove_node` | `node` | Fails if another node still reads it, unless `cascade: true` |
| `connect` | `from {node, port}`, `to {node, port, index?}` | Type, arity and cycle checks; `index` for variadic ports |
| `disconnect` | `to {node, port, index?}` | |
| `set_param` | `node`, `param`, `value` | Checked against type, units and range |
| `set_label` | `node`, `label` | Display only; ID unchanged |
| `set_flags` | `node`, `muted?`, `bypass?` | Bypass passes the first input through when types allow |
| `set_op_version` | `node`, `version` | Explicit upgrade; reports parameter migration or refuses |
| `set_output` | `name`, `from` | Declares which node is a named result |
| `define_material` / `remove_material` | `id`, `def` | Materials are data, assigned by a node parameter |
| `editor_set_position` | `node`, `x`, `y` | Editor layer only |
| `editor_set_collapsed` | `node`, `collapsed` | Editor layer only |
| `editor_set_frame`, `editor_add_reroute` | defined with V2 | Editor layer only |
| `create_group` | `name`, `members`, `output`, `alias?` | Existing nodes become the definition (version 1); members read only each other and nothing outside reads them (`group.leaks`); the result must be a solid |
| `remove_group`, `set_group_name` | `group`, `name?` | Removal refused while instances exist (`group.in_use`); it takes the members with it |
| `expose_param`, `unexpose_param` | `group`, `name`, `node?`, `param?` | Interface changes: the group's version increases by one |
| `set_group_output` | `group`, `node` | Interface change unless it names the current result |
| `add_instance` | `group`, `label?`, `alias?`, `into?` | An instance pinned to the current version; `into` nests it in another group (recursion is `group.recursive`, depth over 8 is `budget.group_depth`) |
| `set_instance_param`, `clear_instance_param` | `node`, `param`, `value?` | Overrides one exposed parameter on one instance, checked against the member parameter's own type and range; `group.outdated` while the instance is behind |
| `upgrade_group` | `node` | Moves one instance to the group's version; keeps overrides that still match, drops the rest (`upgrade_preview` says which); `group.up_to_date` if there is nothing to do |
| `add_node` with `group` | as `add_node` | Adds a member of a group's definition; `group.input@1` is only valid this way and changes the interface |

Transforms are nodes (`xform.move`, `xform.rotate`, `xform.scale`), so the inspector and gizmos edit
those nodes' parameters with `set_param`. Undo and redo are session requests (`undo`, `redo`), not
commands: they carry a request ID and move along recorded transactions.

`poly.subdivide@1(cage, levels=1)` accepts simple concave planar n-gons: each concave face is
triangulated before Catmull-Clark and reports `poly.subdivide.concave_face_triangulated`. Convex
faces keep their cage topology. This adds diagonal edge flow across concave faces; keep the warning
in mind when downstream selection depends on edge layout.

## Organic sculpting

`poly.sculpt@1(mesh, strokes="...", falloff="surface")` applies up to 64 ordered brush strokes.
The brushes are `draw`, `inflate`, `smooth`, `flatten`, `pinch`, `grab`, `mask` and `unmask`;
`grab` takes a displacement vector, while the others take a strength. `falloff="surface"` measures
distance over connected mesh edges, so a brush does not reach through the opposite side of a head
or a thin shell. Use `falloff="sphere"` for the prior world-space behavior. `mask` and `unmask`
write the persistent point channel `sculpt_mask`; subsequent geometry strokes are weighted by the
remaining unmasked amount. This channel survives chained sculpt operations and subdivision.

```text
cage = poly.from_solid@1(body)
dense = poly.subdivide@1(cage, levels=1)
masked = poly.sculpt@1(dense, strokes="mask 0 1.2 0.1 0.18 1", symmetry="x", falloff="surface")
shaped = poly.sculpt@1(masked, strokes="draw 0 1.2 0.1 0.18 0.025; smooth 0 1.2 0.1 0.2 0.25", symmetry="x", falloff="surface")
```

The mesh must already have enough vertices for the requested detail; subdivide or remesh before
sculpting. Surface falloff follows mesh connectivity, so disconnected UV or topology seams do not
share brush influence unless the vertices are welded.

On `body.human`, this operator keeps the source-point map, skin weights and rig landmarks. The
edited body can feed `body.skin`, `body.eye`, `body.hair`, and body-fitted clothing directly. Keep
the operation topology-preserving: remeshing and subdivision need explicit weight and landmark
transfer before they can be inserted into a rigged character graph.

```text
body = body.human@1()
face = poly.sculpt@1(body, strokes="grab 0 1.65 0.12 0.16 0 0 0.01", falloff="surface")
eyes = body.eye@1(face)
hair = body.hair@1(face, density=0.6, length=0.18)
skin = body.skin@1(face, bones="root; spine01; spine03; head")
```

## Character shape keys

`rig.morph@1(base, target, name="smile", weight=1)` creates a glTF shape key from an equal-topology
edited copy. Make every expression from the neutral mesh, then chain `rig.morph` nodes on the output
to retain prior keys. The node previews the chosen weight in the viewport and exports each name,
weight and point delta as a glTF morph target. It supports up to 16 keys and 500,000 points per part.

```text
neutral = body.human@1(face="jawOpen=0")
smile = poly.sculpt@1(neutral, strokes="grab 0 1.62 0.14 0.12 0 0 0.02", falloff="surface")
expression = rig.morph@1(neutral, smile, name="smile", weight=0.65)
blink = poly.sculpt@1(neutral, strokes="flatten 0 1.70 0.15 0.08 0.4", falloff="surface")
face = rig.morph@1(expression, blink, name="blink", weight=0)
```

The target must preserve point count and face topology. Remesh, subdivision and other topology
changes need a separate transfer step before they can become a shape key.

## Results
```json
{ "committed": { "revision": 13, "transaction": "t_01HZ...", "changed": ["n_a1b2c3d4"] } }
{ "rejected":  { "diagnostics": [ { "code": "param.range", "severity": "error", "node": "n_a1b2c3d4", "...": "..." } ] } }
{ "conflict":  { "base_revision": 12, "current_revision": 14, "changed_since": ["n_a1b2c3d4"] } }
{ "already_applied": { "revision": 13 } }
```
A conflict never partially applies. Providers must rebase and resubmit; the engine does not merge
silently. A pending batch superseded by a newer one is merged only when the two touch disjoint nodes;
otherwise the later one gets a conflict.

## The vase transaction (frozen example for G3)
Operators used: `profile.polygon@1`, `solid.revolve@1`, `solid.difference@1`, `check.min_wall@1`.
```text
outer   = profile.polygon(points=[[0,0],[0.06,0],[0.11,0.12],[0.07,0.26],[0.05,0.30],[0,0.30]])
inner   = profile.polygon(points=[[0,0.01],[0.056,0.01],[0.104,0.12],[0.064,0.26],[0.040,0.31],[0,0.31]])
wall    = check.min_wall(outer, inner, min=0.003)
body    = solid.revolve(outer, angle=360, segments=64)
cavity  = solid.revolve(inner, angle=360, segments=64)
vase    = solid.difference(body, cavity)
output vase
```
`inner` rises above the rim, which opens the vase. `check.min_wall` measures the cross-section
`outer` minus `inner` (any two profiles) and requires every part of it to be at least 3 mm thick.
The open cap and rotation axis are not walls. Full eroded-profile containment would reject this
deliberate rim opening. [ADR 0010](../adr/0010-first-language-numeric-contracts.md) records the
correction to the original inner radius and how the check works.

"Widen its opening" is one batch with two `set_param` commands (the last off-axis point of `outer`
moves 0.05 to 0.07 and of `inner` 0.040 to 0.064), keeping both node IDs, and `wall` still passes.
A batch that widens only `inner` would thin or break the wall: it must be rejected by `wall` with
`constraint.min_wall`, naming `wall`, `outer` and `inner`, and the document stays unchanged.
Sequence: create (mock provider) -> select `vase` in the viewport -> widen opening -> manual edit of
`segments` in the inspector -> undo -> reload. IDs and parameters match at each step.
# Cloth and skin transfer

`body.outfit(body, asset, standoff, bones)` fits real CC0 clothes and hair (ADR 0056) to a body.human and skins them with its weights. `body.skin_to(cloth, body, bones="root; spine01; ...")` transfers the nearest body's authored skin weights to a cloth solid for animation.
