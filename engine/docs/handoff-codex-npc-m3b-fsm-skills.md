## What to build (names and signatures fixed by the contract test)

### Hierarchical state machine: `Fsm`
- `Fsm::from_json(&str) -> Result<Fsm, BrainError>`, `from_json_with_library(&str, &BTreeMap<String, String>) -> Result<Fsm, BrainError>` (linked machines by name, resolved at build time; a missing name or a link cycle is a build error naming it), `to_json(&self) -> String` (stable; linked states may be serialised inlined), `validate(&self, &Registry) -> Result<(), BrainError>` (one `UnknownNames` error listing every unknown condition and action name), `start(&mut self, &mut Registry, &mut Ctx) -> Result<(), BrainError>` (enters the initial path, running `on_enter` actions outer to inner and recording `ctx.now` as the enter time of every state on the path), `tick(&mut self, &mut Registry, &mut Ctx) -> Result<FsmTick, BrainError>`, `send_event(&mut self, &str)`, `state_path(&self) -> Vec<String>`. `FsmTick { pub path: Vec<String>, pub changed: bool }` (Clone, Debug).
- JSON: `{"initial": "name", "states": {"name": State, ...}}` where a `State` has optional `on_enter`, `on_update`, `on_exit` (names of registered actions; the returned `Status` is ignored), optional `transitions: [{"to": "sibling", "when": When}]` in priority order, optional nested `{"initial", "states"}` (a composite state; its `initial` is required when `states` is present), optional `link: "name"` (the state's nested machine is the named library machine; a state may have `link` or inline `states`, not both; a linked machine's own top-level `initial` and `states` become the state's children). `When`: `{"condition": name}`, `{"check": {"key","op","value"}}` (same comparison semantics as the behaviour-tree `check` node), `{"after": secs}` (seconds since this state was entered, compared with `ctx.now`), `{"event": name}` (true when that event was sent since the last tick), `{"not": When}`, `{"all": [When]}`, `{"any": [When]}`. Build errors (`BrainError::BadSpec`): invalid JSON, `initial` not among the states, a transition target that is not a sibling state, no states, bad `op`, unknown `When` type, `link` together with `states`.
- Tick semantics: first, each active state from the **innermost** to the outermost is checked in order: the first state (inner first) that has a transition whose `when` is true takes it (transitions inside a state are tried in list order); **at most one transition is taken per tick**. Taking a transition exits the active states below the one that owns the transition (inner to outer) and that state itself (`on_exit`), then enters the target (`on_enter`), then enters the target's `initial` descendants recursively (outer to inner, `on_enter` each); every entered state records `ctx.now`. If no transition was taken, run `on_update` for each active state outer to inner. After the tick, all events are cleared. `FsmTick.changed` says whether a transition was taken. When a transition is taken `on_update` does not run that tick.

### Skill stack: `SkillStack`
- `SkillStack::new()`, `add(&mut self, name: &str, priority: u8, when: Option<&str>, tree_json: &str) -> Result<(), BrainError>` (names are unique: duplicate is `BadSpec`; the tree JSON is a behaviour tree and a parse error is returned), `validate(&self, &Registry) -> Result<(), BrainError>` (lists every unknown condition and action name across all skills), `tick(&mut self, &mut Registry, &mut Ctx) -> Result<SkillTick, BrainError>`. `SkillTick { pub active: Option<String>, pub status: Status, pub switched: bool }`.
- Tick: the candidate skills are those whose `when` condition holds (`None` means always); the active skill is the candidate with the highest priority, ties to the one added first. If it differs from the previously active skill (or there was none), the previous skill's tree is `reset()` and `switched` is true (including the very first choice). Then the active skill's tree is ticked and its status returned. When a skill's tree finishes (Success or Failure) it simply runs again next tick while it is still chosen (the tree resets itself on completion). No candidate gives `active: None`, `status: Failure`, `switched` true only if something was active before.
