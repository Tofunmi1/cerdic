Design hints: resample the path as a centripetal Catmull-Rom spline at half-cell spacing; for each cell find the nearest point on the spline (a grid of segment buckets) and its distance `d` and tangent; the bank top height is the original ground at that cell blended from the ground at distance `width / 2 + bank_width`; the bed profile across the channel is flat in `width / 2` then rises by the bank slope to meet the ground; the water surface is `bank top - water_level_offset`; flow direction is the tangent, flow speed grows with depth and the slope of the water surface along the path. Road: sample the original ground along the path at 1 m spacing, smooth it, then clamp successive differences to `max_grade_percent / 100` per metre (forward then backward pass), add the crown across the width, and blend the corridor into the ground with the embankment angle; `cut_fill` is the sum of absolute height changes times the cell area. Shore: `beach = 1 - smoothstep(0, beach_width, height - level)` for ground at or above the level, 0 below; `wet_rock` is the slope mask (angle over 90 degrees) where the height is within 1.5 m above the level; `underwater` is 1 below the level. Temperature and moisture as documented in `climate.rs` (moisture by a two-pass chamfer distance transform to wet cells, then `1 - smoothstep(0, moisture_distance, distance)`).

## Why
In shipped open worlds rivers and roads are splines that reshape the ground and drive materials and water, not just masks. This crate carves them into a tile in WORLD coordinates so a river crossing many tiles lines up, and produces the data the water mesh and the ground material need.

## Rules
- Core crate. Deterministic and platform-identical (`+ - * /`, `sqrt`, polynomial smoothstep; no std trig). Cancellation per row. All geometry in WORLD metres. A path may cross tiles: processing each tile separately must equal processing the joined grid (tile invariance tests).

## API to build (signatures are fixed; tests will import these)
```rust
pub struct Path { pub points: Vec<[f32; 2]> } // world xz polyline; internally Catmull-Rom resampled at cell/2 spacing (centripetal, as `curve.spline` does)

pub struct RiverProfile { pub width: f32, pub depth: f32, pub bank_slope_deg: f32, pub bank_width: f32, pub meander_flatten: f32 /* 0..=1 smooths the valley floor across the channel */, pub water_level_offset: f32 /* metres below the surrounding bank top */ }
pub struct RiverOut { pub water_height: Vec<f32> /* per cell, NaN-free; terrain height where there is no water */, pub flow_dir: Vec<[f32; 2]> /* unit xz direction of flow per cell, zero outside the channel */, pub flow_speed: Vec<f32>, pub bank_mask: Vec<f32> /* 0..=1 wet bank/sand */, pub channel_mask: Vec<f32> }
/// The river runs downhill: the path is monotonically lowered along its length (never uphill); each cell is carved to the channel profile with bank shaping, reporting the water surface for the water mesh and the flow field for a flow-map shader.
pub fn carve_river(heights: &mut [f32], width: usize, depth: usize, cell: f32, origin: [f32; 2], path: &Path, profile: &RiverProfile, cancel: &dyn Fn() -> bool) -> Result<RiverOut, RiverError>;

pub struct RoadProfile { pub width: f32, pub shoulder: f32, pub max_grade_percent: f32, pub crown: f32 /* cross-slope for drainage, metres at the centre */, pub embank_slope_deg: f32 }
pub struct RoadOut { pub road_mask: Vec<f32>, pub shoulder_mask: Vec<f32>, pub cut_fill: f32 /* total cubic metres moved, for diagnostics */ }
/// Flattens a corridor along the path: the road height follows the terrain but is limited to `max_grade_percent` per metre of path (smoothed profile), cut and fill blend into the surrounding ground with the embankment angle.
pub fn carve_road(heights: &mut [f32], width: usize, depth: usize, cell: f32, origin: [f32; 2], path: &Path, profile: &RoadProfile, cancel: &dyn Fn() -> bool) -> Result<RoadOut, RiverError>;

/// Shoreline: distance to the water level, for beach sand and wet-rock masks. `level` is a world-space water height.
pub fn shore_masks(heights: &[f32], width: usize, depth: usize, cell: f32, level: f32, beach_width: f32, cancel: &dyn Fn() -> bool) -> Result<ShoreOut, RiverError>;
pub struct ShoreOut { pub underwater: Vec<f32>, pub beach: Vec<f32>, pub wet_rock: Vec<f32> /* steep cells near the water line */, pub depth_below: Vec<f32> }

/// Climate and biome channels: pure functions from terrain channels to the inputs the species rules (ve-scatter) read.
pub struct Climate { pub sea_level: f32, pub lapse_per_km: f32 /* temperature drop per 1000 m, degrees C */, pub base_temperature: f32, pub latitude_gradient: f32, pub moisture_distance: f32 /* metres over which closeness to water adds moisture */ }
pub fn temperature(heights: &[f32], width: usize, depth: usize, cell: f32, origin: [f32; 2], c: &Climate) -> Vec<f32>;       // degrees C
pub fn moisture(heights: &[f32], channel_or_water: &[f32], width: usize, depth: usize, cell: f32, c: &Climate) -> Vec<f32>; // 0..=1 from distance to water plus flow accumulation input
```
`RiverError`: `Cancelled`, `BadPath { why }` (fewer than 2 distinct points, path leaves the grid entirely), `BadShape`, `BadParameter { name, why }` (negative width, bank angle outside 5..=85, grade over 40 percent).
