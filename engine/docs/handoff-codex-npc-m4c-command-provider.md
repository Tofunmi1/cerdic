## What to build

- `CommandProvider` (native only): `CommandProvider::new(program: &str) -> Self`, `args<I: IntoIterator<Item = S>, S: AsRef<str>>(self, args: I) -> Self`, `with_timeout(self, Duration) -> Self` (default 60 s), `respond(&mut self, &Request) -> Response`. Behaviour: spawn the program with the args, standard input piped, standard output and standard error piped; write the prompt to stdin **on a separate thread** and close it (a prompt of hundreds of kilobytes must not deadlock against a program that streams output), read stdout and stderr to the end on their own threads; wait up to the timeout (poll `try_wait` every 10 ms or use a channel with `recv_timeout`); at the timeout kill the child (and wait for it so no zombie is left) and return `Err("timed out after <secs> s")`. Result: exit status 0 and non-empty trimmed stdout gives `Ok(trimmed stdout)`; a non-zero exit gives `Err("exit code <n>: <first 300 characters of stderr, trimmed>")`; a program that cannot be started gives `Err("cannot start <program>: <io error>")`; empty output with exit 0 gives `Err("empty reply")`. The `Response.id` is the request's id. No panics.
- `run_until_idle(host: &mut NpcHost, provider: &mut CommandProvider, now: f64, max_requests: usize) -> usize`: repeatedly `host.take_outbox()`, answer each request with `provider.respond`, `host.deliver(response, now)`, until the outbox is empty or `max_requests` have been handled in total; returns how many were handled. (Sequential is fine; the example is a development tool.)
- Example `chat.rs`: `cargo run -p ve-npc --example chat -- [--npc-file path.json] --cmd "<shell command>" [--timeout secs]`. It builds one `NpcHost` with one NPC (from the JSON `NpcSpec` file if given, else a built-in baker named `anna`), runs the command through `sh -c` for each prompt (the prompt on stdin), and loops: read a line from stdin (empty line or end of input quits), `player_says`, `run_until_idle`, print the NPC's reply (the last transcript turn, marked `[canned]` when `fallback`), print on stderr a one-line summary: the milliseconds the model took, how many intents were valid and how many were rejected (the host's last `Delivery` is enough: if you need it, have `NpcHost::deliver` keep the latest `Delivery` for `last_delivery(npc) -> Option<&Delivery>`; adding that accessor to the host is allowed). A `:memory` line prints the NPC's ten most recent memories, `:save file` writes `host.to_json()`. This is for Claude to run a real conversation with a real model and measure how often replies are valid; keep it small.
