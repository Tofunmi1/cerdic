# ADR 0063: ve-nav is an extensible navigation and NPC framework, not a navmesh

Status: accepted (owner, 2026-10-24: "very very extensible, for any kind of game and npc"). Detail record for the work in `plans/game-world-system.md` M3 (navigation nodes and agents, E1) and M4 (playtest bots).

## Context

`ve-nav` today (2,100 lines) is one closed pipeline: triangles to a flat walkable grid of one agent size, A* over it, a funnel, a small crowd, and four goal pickers (wander, patrol, chase, flee). Nothing else is expressible: no water or lava that a creature may cross at a price, no doors, ladders, jumps or teleports, no flying or swimming, no two agent sizes in one world, no blocked-by-a-crate until the next rebuild, no hearing or sight, no decisions beyond a goal picker. A game maker has to host a guard, a deer, a dragon, a shopkeeper, a zombie horde, a drone, a pet, a boss; each needs a different space to move in, different movement, different senses and a different way of deciding. What the research on shipped engines shows (Recast/Detour and its tile cache, Unity and Unreal navigation, Unity's A* Pathfinding Project, RVO2/ORCA crowds, behaviour trees, utility AI, GOAP) is that nobody hard-codes these. They are **separate layers behind small interfaces**, and a game picks and mixes: Detour keeps *areas* and *flags* on polygons plus a per-query *filter* (so one navmesh serves several kinds of agent), *off-mesh connections* for jumps and ladders, and a *tile cache* for obstacles that appear at runtime; RVO2 deliberately does only local avoidance and leaves the global plan to the application (the application supplies each agent's preferred velocity); AI practitioners recommend matching the decision technique to the job (utility to choose, state machines to switch, behaviour trees to execute, planners where goals are open) rather than choosing one.

## Decision

`ve-nav` becomes a set of **layers with open extension points**. All of it is pure Rust, deterministic (fixed steps, seeded random, stable order, no hash-map iteration order), wasm-safe, bounded (every search and tick has a budget and refuses with a typed error), and **data-first**: every layer is describable by a small text spec so a model writes it through the language (principle: everything via the language), and every extension point is a trait plus a **name registry**, so a game, a node or a spec can refer to a custom piece by name. It stays in one crate as modules (owner rule: few crates).

```
 decide     Brain (FSM | behaviour tree | utility | planner | custom)  reads Blackboard, writes Commands
 perceive   Senses (sight, hearing, touch, custom) -> Percepts -> Blackboard (with memory and decay)
 act        Commands (move_to, stop, look_at, use, say, custom) -> Locomotion + Steering
 move       Steering stack (follow path, arrive, separate, avoid (ORCA 2D/3D), custom) + Locomotion (ground, fly, swim, climb, rail, hop, custom)
 route      Search over any NavSpace with a CostFilter (areas, edge kinds); time-sliced queries; path cache; hierarchical for large worlds
 world      NavSpace implementations: walkable grid (today), polygon mesh, waypoint graph, 3D volume, layered floors, road/rail graph, custom
            + annotations: areas (u8 ids), links (jump, ladder, door, teleport, custom), dynamic overlay (obstacles, cost volumes, doors) with a version number
```

### Extension points (each is a trait, object-safe, with a registry)

1. **`NavSpace`**: what is navigable. `node_count`, `position`, `area`, `neighbours(node, out)`, `locate(point)`. The search never sees a grid or a mesh, only nodes and edges, so any structure that can list neighbours is a space: a grid, a polygon mesh, hand-placed waypoints, a 3D voxel volume for flyers and swimmers, stacked floors, a road network, a card-game board.
2. **Areas and edge kinds are open ids** (`AreaId` 0 to 63, `EdgeKind` 0 to 63; a few named constants like `GROUND`, `WATER`, `WALK`, `JUMP`, `CLIMB`, `DOOR`, `TELEPORT`, the rest free for a game's own). A game names them in its spec (`area water = 2`).
3. **`CostFilter` per agent type**: which areas may be entered, a cost multiplier per area, which edge kinds may be used and at what multiplier. One world, many agent types: a deer avoids roads, a guard avoids water, a boat needs it, a drone ignores areas and uses `FLY` edges.
4. **`AgentType`** (data): radius, height, step, slope, speeds, acceleration, turn rate, locomotion mode, its `CostFilter`, its senses and its brain by name. Several types share one world; a space can be built per type or shared (Detour's approach) as the space declares.
5. **`Steer`** behaviours compose into a stack with weights and priorities: seek, arrive, flee, wander, follow path, separate, align, cohesion, avoid (ORCA), obstacle avoid, custom. **`Locomotion`** turns a desired velocity into motion for its mode (ground sticks to the surface and respects slope and step, flyers hold an altitude band, swimmers a depth band, climbers follow a link, rail agents follow a graph, hoppers move in arcs).
6. **`Sense`**: sight (radius, cone, line of sight through the space), hearing (events with a loudness and falloff), touch, custom. Output is `Percept`s written to a **`Blackboard`** (typed key-value store with times, expiry and per-key memory decay) so brains see "last known position of the player 3 s ago".
7. **`Brain`**: reads the blackboard, returns **`Command`s** for the game (move to, stop, look at, use, say, play clip, set blackboard value, emit event, custom). Provided brains, all data-described and all able to nest in each other: finite state machine, behaviour tree (sequence, selector, parallel, decorators, conditions and actions by name), utility (scored considerations with response curves), and a goal-oriented planner later. A hybrid is just one brain choosing another (utility picks a behaviour tree).
8. **Registries**: named **conditions**, **actions**, **considerations**, **steering behaviours**, **senses** and **cost functions**. A game or a node registers its own (`guard.alert`, `shop.open`); specs and graph nodes name them. No engine change is needed to add an NPC kind.
9. **Overlay**: dynamic changes without a rebuild: obstacles (cylinder, box, oriented box), cost volumes (a fire zone costs 8), area repaints, door and link state (open, locked, one-way), each change bumps a version; running agents whose path crosses a changed region repath. A `NavSpace` implementation opts in by honouring the overlay.
10. **Authoring spec**: a line-per-statement text format in the style of `ve-game` (`agent_type guard radius=0.4 speed=2.5 areas=ground,road avoid=water brain=patrol_guard`, `link jump from=.. to=.. cost=..`, `brain patrol_guard bt ...`). The graph nodes `nav.*` and the runtime wiring are thin layers over the same spec, so the model, a person in the editor and a saved game all use one description.

### Rules for every layer

- Pure data in, pure data out, no global state, no clock: time is a parameter (`dt`), randomness is a seeded generator that is part of the state, so a replay, a playtest bot and a networked client agree.
- A tick and a query have budgets (agents per crowd, expansions per search, queries per frame time-sliced across frames); exceeding one is a typed error or a deferred result, never a hang.
- Everything observable is exportable for the viewer: paths, spaces (nodes and edges), blockers, perception cones, brain state (which BT node, which FSM state, utility scores), so the owner can *see* what an NPC is thinking, and so a model can read it as text.
- Compatibility: the existing `NavMesh`, `Crowd`, `Agent`, `Path` and goal pickers keep working and keep their tests; they become the first implementations of the new traits.

## What shipped AAA games do, and how each lesson lands here

Research 2026-10-24. Sources: Guerrilla's Horizon Zero Dawn AI articles and GDC 2018 talk (Berteling), Josemans' "Putting the AI back into air" slides, the Last of Us case study (arXiv 2207.00682) and Dyckhoff's GameAIPro chapter on Ellie, Epic's Mass Entity, ZoneGraph, StateTree and Smart Objects documentation and the CEDEC 2022 deck, Cournoyer's GDC 2015 "AI Recycling" talk on Assassin's Creed Unity. The engines' code is not available to us, so we take the **architectures**; open algorithms (Recast's pipeline is zlib, RVO2 is Apache 2.0) we may study and re-implement in our own Rust.

1. **Layered, each layer replaceable.** Horizon: a world *Collective* (spawning, balancing, group membership) over **group agents** (no body; a shared blackboard of safe areas, patrol routes and what the herd knows; roles with caps: patrol, search, attack, scavenge, flee) over **individual agents** (sensors plus a planner) over navigation and animation. Groups do not tick every frame, so there is no hive mind. Lands here: a **Group** layer with a shared blackboard, role assignment with caps and tickets (N6), above individual brains.
2. **Decide with a planner plus a score, not one technique.** Guerrilla: an **HTN planner** (designer-authored *macros*, fixed action sequences) with a **utility score** as a precondition (how interesting is this attack now) so that not everything attacks at once and the others circle and wait. Naughty Dog: **skills** in a priority queue (a higher one interrupts a lower: panic, advance, melee, flank, investigate) over a low-level **behaviour stack** (MoveToLocation, StandAndShoot, TakeCover); skills are shared across character types, so two enemy kinds share code and feel different. Lands here: N6 gets an **HTN brain** and the **skill stack** shape next to FSM, behaviour tree and utility.
3. **Position queries, scored by criteria multiplied together.** The Last of Us: each NPC gets 20 cover posts, raycast-checked within a fixed ray budget, rated by data-written criteria (17 selectors; the key one: the route must not cross the player), the best product wins; Ellie's follow positions come from rays out of the player; Horizon's landing spots are navmesh candidates filtered by height. Same pattern as Unreal's environment queries. Lands here: a first-class **Query** layer (N5): a *generator* (ring, along the space, around a target, cover posts, lanes), *criteria* (distance band, visible to or from, exposure, route does not cross X, path cost, custom by name) multiplied into a score, with a ray and query **budget**, time-sliced.
4. **Perception that is tuned, not textbook.** A single cone misses a player standing next to the NPC; The Last of Us widens and narrows the angle with distance, Alien: Isolation uses four cones; the Infected are blind and driven by hearing; search is **area coverage** (a grid of unseen cells, pick the animation or spot that reveals most). Lands here: N5 senses take a **distance-dependent cone** (a curve), several cones per sense, hearing as events with loudness, an **exposure map**, and **coverage search**.
5. **One space per kind of mover, sized per agent.** Horizon's airspace is a **height map** (per cell the highest collision plus the agent radius: no flying under arches, but far cheaper than voxels, octrees or waypoint graphs), built as runtime tiles only in bubbles around agents, cell size per agent size, **hierarchical A\*** over max-mipmaps (coarse path at level 3, refine in that corridor at levels 1 and 0, hard stop at 1024 iterations returning the best finished path, so cost is bounded and a path always comes back; about 33% extra memory), smoothing by recursive raycast that keeps running while flying, landing by filtering navmesh candidates against the height map, **hover** (facing differs from heading) versus **glide** locomotion. Lands here: N3's flying space is a height-map space with per-agent cell size, max-mip hierarchy and an iteration cap that returns the best partial path; N4 has hover and glide.
6. **Crowds are data, lanes carry tags, interactions are claimed slots.** Unreal Mass: entities are plain data (**fragments**) run by **processors**, thousands of agents; the crowd moves along **ZoneGraph lanes** with tags (Spawn, Wander, Patrol, JobApproach; spawners and tasks *query lanes by tag*; short approach and exit lanes around a prop keep agents off main traffic); behaviour is a **StateTree** (hierarchical states, parameters, evaluators, transitions, linked reusable trees); interactions are **Smart Objects** with slots (find, **claim**, go, arrive and align, use, **release**, cool down; claims may be asynchronous, so wait, never fail); avoidance is a steering trait; behaviour asks for animation **by name** and a data asset maps it to a clip. Lands here: N3 **tagged lanes and a lane query**; N2 **smart objects** (slots, claim handles that must be released, alignment tolerance, cooldown); N6 a **hierarchical state machine with linked trees**; N8 **struct-of-arrays** agent state; N7 **named animation requests** mapped to clips.
7. **Simulation level of detail.** Assassin's Creed Unity: 10,000 crowd NPCs on screen with 40 fully simulated AIs and 120 high-resolution models, by "AI recycling": a pool swaps low-resolution bulk agents for full agents near the player and back (three tiers: lowest-resolution bulk, autonomous bulk, puppet bulk). Mass does the same with representation tiers by distance, importance, density and platform budget. Lands here: N8 **simulation tiers per agent** with promotion and demotion and a pool.
8. **Do not visibly cheat.** The buddy teleports only when needed and out of sight; herds react only when the group ticks. Lands here: a per-agent **cheat policy** (teleport only when unseen and out of reach, bounded speed catch-up) enforced by the locomotion layer and shown in the report.
9. **Designers author macros, tags and criteria as data, not code.** Lands here: everything above is a spec line a model can write, and the registries let a game add its own named pieces.

## Steps (each ends with fixed tests written by Claude, run by Claude; Codex implements one narrow step at a time; one agent per crate)

- **N1 Core:** `NavSpace`, `AreaId`, `EdgeKind`, `CostFilter`, generic deterministic A* with budget over any space, `NavMesh` as a space with area painting. Tests: `crates/ve-nav/tests/space.rs`.
- **N2 Links, smart objects and overlay:** off-mesh links (jump, ladder, door, teleport, one-way, locked), **smart objects with claimable slots** (claim handle, approach and exit lanes, arrival alignment, cooldown), dynamic obstacles and cost volumes with versions, repath on change.
- **N3 More spaces:** waypoint graph with **tagged lanes and a lane query** (roads, rails, patrol routes, board games), **height-map airspace** (per-agent cell size, max-mip hierarchy, iteration cap, partial path) for flyers and swimmers, layered floors, polygon mesh with portals; smoothing that keeps running while moving.
- **N4 Movement:** the steering library, ORCA avoidance in 2D and 3D, locomotion modes (ground, hover, glide, swim, climb, rail, hop), the cheat policy, agent types as data, multi-type crowds.
- **N5 Perception and queries:** senses with distance-dependent cones, hearing events, blackboard with memory, exposure maps, coverage search; **position queries** (generators, criteria multiplied into a score, ray and query budgets, time-sliced).
- **N6 Brains:** FSM and **hierarchical state machine with linked trees**, behaviour tree, utility, **HTN planner with macros and utility preconditions**, the **skill stack** (prioritised interruptible skills over reusable behaviours), registries of named conditions and actions, nesting; **group agents** with a shared blackboard, roles with caps and tickets, and a world-level collective that spawns and balances.
- **N7 Authoring and wiring:** the text spec and parser, `nav.*` graph nodes, runtime systems (agents driving rigged parts, **named animation requests mapped to clips**, events into `ve-game`), viewer overlays and a text "what is it thinking" report, checks (`walkable_path`, `goal_reachable`, `no_softlock`).
- **N8 Scale:** time-sliced queries, path cache, tiled spaces with streaming, hierarchical search or flow fields for hundreds of agents, struct-of-arrays agent state, **simulation tiers with a recycling pool** (full, cheap lane-follower, statistical), performance budgets on the Quest throttle.

## Consequences

More surface than a navmesh crate needs for one game, in exchange for not rewriting it per genre. The cost is guarded by the steps: nothing is built without a test fixed first, and each step ships a demonstration (a deer that avoids roads and wades through shallows at a price; a guard that opens doors; a drone over a canyon; a crowd on a road network; a shopkeeper that notices you and decides).

Open for the owner later: whether a planner (GOAP) is wanted in N6 or stays a later add-on; whether agent types share one built space (Detour style) or each gets its own (simpler, more memory); networking of navigation state.
