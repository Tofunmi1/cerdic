# ADR 0051: Wind as a vertex-shader field

- Status: accepted
- Date: 2026-10-19

## Context

`solid.foliage` already carried `sway` and `flutter` per surface, packed into the instance data, but nothing animated them. Trees and grass need to move, for thousands of instances, without per-frame CPU work and without
rebuilding meshes. The shadows and the occlusion depth pass must move the same way as the picture, or foliage would shade itself with its rest pose.

## Decision

1. **One global field, in the view uniform.** `WindField` (`ve-render/src/wind.rs`) holds a ground-plane direction, a strength (0 to 2) and a time. It rides in `ViewUniform::wind` (the last lane), written for every view and for
   every sun-shadow cascade. The runtime sets the time from the shared animation clock each frame (pausing the clock holds the foliage still) and the direction and strength from the authored environment on each commit.
2. **The displacement is a vertex function** `wind_displacement(origin, world, local, foliage)`, the same text in `forward.wgsl`, `shadow.wgsl` and `ao_depth.wgsl` (a test keeps the three identical). Sway moves the vertex downwind by
   `sway * strength * 0.06 * h^2` metres, where `h` is its height above the instance origin (0 to 6 m), times a gust made of three sines whose phase travels across the ground so neighbours are out of step, plus a little sideways;
   the lean lowers the vertex as it goes so the shape swings rather than shears. Flutter adds a high-frequency tremble keyed on the vertex's own position. With no sway, no flutter or no wind the function returns zero, so
   everything else is untouched and a scene without foliage pays one branch.
3. **Authored on the environment nodes.** `scene.environment` and `scene.sky` take `wind_direction` (degrees, 0 is +x, 90 is +z) and `wind_strength` (default a gentle 0.5). `SceneEnvironment.wind` carries them; when both nodes
   are authored the environment node's non-default wind wins. The runtime validator bounds them.

## Consequences

- A browser test (`web/tests/g11-wind.mjs`): a card without sway does not move between two clock times (0.00 px), a swaying one's top moves 94 px and leans downwind while its base stays near still.
- The normal is not bent, so lighting does not change as foliage leans; a tilt of a few degrees is invisible next to the sun's direction, and it saves a second cofactor in the vertex stage.
- Bending needs vertices: a flat quad or box only shears. Tree and grass kits must be built with enough rings and segments (curve tube rings already are).
- Exported glTF has no wind: the exporter writes the cutout and two-sided flags but not `sway` or `flutter`, so wind is a viewer feature (a runtime that wants it can read the node graph).
- Not yet done: per-species gust frequency, trunk-versus-branch hierarchy (two-level sway), and wind-driven particles.
