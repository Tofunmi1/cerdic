## What to build (names fixed by the contract test)

- `SecretSpec { pub text: String, pub min_trust: f32, pub markers: Vec<String> }` (Clone, Debug, PartialEq, serde). `NpcHost::add_secret(&mut self, npc: &str, SecretSpec) -> Result<(), HostError>`, `set_examples(&mut self, npc: &str, examples: Vec<(String, String)>) -> Result<(), HostError>` (player line, the NPC's answer; only the **first eight** are used), `set_deflections(&mut self, npc: &str, lines: Vec<String>)` (no error for an unknown NPC; ignore it; default line `"Let's talk about something else."`), `leaks_blocked(&self, npc: &str) -> u32`.
- **Gating**: when building a prompt for an NPC, a secret is *unlocked* when `memory.relationship("player").trust >= min_trust`. Unlocked secrets appear in a new prompt section `## Secrets you hold` (bullets, after `## State`, before `## Memories`; add the field to `PromptSections` as `secrets: Vec<String>` **with the existing struct literals in tests still compiling: if that cannot be done, add the secrets to the `state` lines under a `Secrets you hold:` prefix instead and say so**). **Locked secrets never appear in any form.** If at least one secret is locked, add one fixed line to the **Rules** text of the prompt: `You have private matters you will not discuss; if asked, steer the conversation elsewhere politely.` (no content, no count).
- **Examples**: a prompt section `## Examples` between `## Rules` and `## World`, lines `player: <q>` then `<npc name>: <a>` per example.
- **Leak guard**: in `deliver`, before the delivery is applied to the session and memory, for every `say` intent: if its text (lower-cased) contains any marker (lower-cased, plain substring) of any **locked** secret, replace that `say` text with the next deflection line (rotate through the list deterministically by the number of leaks blocked so far), add `Rejected { raw: <the original text, cut to 200 characters>, reason: "leak guard: marker '<marker>'" }` to the delivery's `rejected`, and increment the counter. The replaced line is what the session shows and what is stored as `<npc> said: ...` dialogue memory (the blocked words are never stored). Secrets with no markers are not guarded (the gate is their protection). Unlocked secrets are not guarded.
- Host save: secrets, examples and deflections are part of `to_json`/`from_json` (save then load then save is identical; counters too).
- JSON surface: `add_secret {npc, secret: SecretSpec}`, `set_examples {npc, examples: [[player, npc], ...]}`, `set_deflections {npc, lines: [..]}` each `{ok: true}` or `{ok: false, error}`.
