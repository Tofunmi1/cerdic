## What to build (new public API, all exported from `lib.rs`; existing API and `tests/nav.rs` keep working unchanged)

1. `space.rs`: `pub type NodeId = u32;`, `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)] pub struct AreaId(pub u8)` with `AreaId::GROUND` (0), `AreaId::new(u8) -> Option<Self>` (None above 63), `pub const MAX: u8 = 63`; `pub struct EdgeKind(pub u8)` (same derives) with constants `WALK` (0), `JUMP` (1), `CLIMB` (2), `SWIM` (3), `FLY` (4), `DOOR` (5), `TELEPORT` (6), everything below 64 usable, ids 16 and up reserved for games' own kinds in the docs;
   `pub struct Edge { pub to: NodeId, pub length: f32, pub kind: EdgeKind }` (Clone, Copy, Debug); and the object-safe trait
   `pub trait NavSpace { fn node_count(&self) -> usize; fn position(&self, node: NodeId) -> [f32; 3]; fn area(&self, node: NodeId) -> AreaId; fn neighbours(&self, node: NodeId, out: &mut Vec<Edge>); fn locate(&self, point: [f32; 3]) -> Option<NodeId>; }`.
   `neighbours` appends to `out` (does not clear it). Edge lists must come out in a deterministic order.
2. `filter.rs`: `CostFilter` (Clone, Debug) with `new()` (every area allowed at cost 1.0, only `EdgeKind::WALK` allowed at cost 1.0), `exclude_area(AreaId)`, `only_areas(&[AreaId])` (allow exactly those), `set_area_cost(AreaId, f32)` (multiplier, finite and >= 0.0; a bad value is ignored or clamped, document which, never panic), `allow_kind(EdgeKind, f32)` (allow and set the multiplier), `allows_area`, `allows_kind`, `area_cost(AreaId) -> f32`, `kind_cost(EdgeKind) -> f32`, and `edge_cost(&self, to_area: AreaId, edge: &Edge) -> Option<f32>` = `None` when the destination area or the kind is forbidden, else `edge.length * area_cost(to_area) * kind_cost(edge.kind)`. Use a `u64` bit mask for allowed areas and for allowed kinds and a `[f32; 64]` for each multiplier.
3. `search.rs`: `pub struct SearchLimit { pub max_expansions: usize }` with `Default` = 200,000; `pub struct NodePath { pub nodes: Vec<NodeId>, pub cost: f32, pub expanded: usize }`;
   `pub fn find_node_path<S: NavSpace + ?Sized>(space: &S, filter: &CostFilter, start: NodeId, goal: NodeId, limit: SearchLimit) -> Result<NodePath, NavError>`: A* with the straight-line distance between `position`s as the heuristic **scaled by the smallest cost multiplier that can occur** so it stays admissible (if the smallest multiplier over allowed areas and kinds is below 1.0, scale by it; at 0 use no heuristic: Dijkstra), a binary heap with the tie-break order (lowest f, then lowest h, then lowest node id) so equal routes always resolve to the same one, a reusable scratch (no per-call hash map iteration; use `Vec` indexed by node id sized `node_count()`), `neighbours` scratch vec reused. The start node is always allowed (an agent standing on a forbidden area can leave it); the goal must be reachable under the filter. Errors: `NavError::UnknownNode(NodeId)` when start or goal is `>= node_count`, `NavError::NoRoute { start: NodeId, goal: NodeId }` when the open set empties, `NavError::SearchLimit { expanded: usize }` when `max_expansions` nodes were expanded without reaching the goal (add these three variants to `NavError` with `thiserror` messages; do not rename existing ones). `start == goal` returns the single node with cost 0 and `expanded` 0.
   `pub fn find_point_path<S: NavSpace + ?Sized>(space: &S, filter: &CostFilter, start: [f32; 3], goal: [f32; 3], limit: SearchLimit) -> Result<Vec<[f32; 3]>, NavError>`: `locate` both ends (`NavError::NoWalkableCell { at }` when `locate` gives none, using the existing variant), run `find_node_path`, return the node positions in order.
4. `impl NavSpace for NavMesh` (the walkable grid): nodes are the walkable cells in a stable order (document it), positions are cell centres at the cell height, `locate` is the existing nearest-walkable lookup, `neighbours` follows the same moves and step rule the existing A* uses (`max_step`, corner cutting rule: reuse, do not re-derive; read `astar.rs` and `grid.rs`), `length` is the true distance between the centres, kind `WALK`, and `area` comes from a new per-cell area id array stored in the grid (default `GROUND`). Add `NavMesh::paint_area(&mut self, min: [f32; 3], max: [f32; 3], area: AreaId)` painting every walkable cell whose centre lies inside the axis-aligned box. Keep memory low: one `u8` per cell.
