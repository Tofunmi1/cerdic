## Behaviour

1. **Admission** in `ask`: (a) per-NPC rate: count that NPC's earlier admitted or queued asks with `issued_at > now - 60.0`; if that count is `>= calls_per_minute` return `Refused(RateLimited)`; (b) token budget: estimated tokens of a prompt = `chars().count().div_ceil(4)`; sum the estimates of all asks (any NPC) admitted or queued in the last 60 s, if adding this one exceeds `tokens_per_minute` return `Refused(OverTokenBudget)`; refused asks are not counted anywhere; (c) otherwise: if the number of admitted-not-yet-taken-or-delivered-or-expired requests (in flight, including ones already taken from the outbox) is below `max_concurrent`, it is `Sent`, else `Queued`.
2. **Outbox**: `take_outbox` returns the admitted requests not yet taken, highest `priority` first, ties by lower id; a queued request becomes admitted (and appears in a later `take_outbox`) as in-flight slots free up, highest priority first (ties lower id). Each request is returned by `take_outbox` exactly once.
3. **deliver**: unknown, already delivered, cancelled or expired id returns `None`. A known one is removed from pending (freeing a slot) and: `Err` outcome, or an `Ok` text from which `parse_reply` yields no intents, becomes a fallback delivery: `fallback: true`, `rejected` kept from the parse (empty for an `Err`), and `intents` = one `say` intent with the NPC's fallback line for the request's `Reason`, if the table has one (line choice: index `fnv1a(npc bytes ++ request id as 8 le bytes) % lines.len()`, so it is stable per run but varies), else empty. Otherwise `fallback: false` with the parsed intents and rejections.
4. **tick(now)**: every pending request (queued or admitted) with `now - issued_at > timeout_secs` expires: removed from pending, and one fallback `Delivery` is returned for it (same rule as an `Err`), in order of id. A later `deliver` for it returns `None`.
5. **cancel_npc** removes all of that NPC's pending requests silently (no delivery).
6. **Recording**: after `start_recording`, every `deliver` that returned `Some` appends `(npc, fnv1a(request prompt), outcome)` to the recording. `recording()` clones it. `to_json` is stable (struct field order, no maps).
