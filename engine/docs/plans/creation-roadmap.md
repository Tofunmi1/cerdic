# Creation roadmap: everything we build so a model or a person can make anything

Owner goal (2026-11-04): be able to create anything, in the browser, procedurally, with an LLM or a person driving the same typed commands. Cover the procedural half of Blender, Houdini and Unreal, keep every result checked, bounded, repeatable and cached. GPL sources are allowed (publishing needs owner approval). No pulled assets.

Legend: `[x]` done and seen working, `[ ]` not done, `[-]` deliberately deferred (the log says why).

How to use this file: work top to bottom inside a part; tick a box only when the item has a test and has been seen working (native test, browser check, or a picture). Add a dated line to the log at the end for every tick. Parts can overlap where noted.

Verified facts this plan rests on (2026-11-04): the text language already has `let`, `{expr}`, `for` loops (numbers only, depth 3, 2,000 statements, inside groups), `|` pipelines and groups; groups return one solid; loops over names or text are rejected; nothing lets a node read another node's evaluated value; no `if`, no macros. Vendored already: Blender (bmesh, geometry, blenlib, blenkernel), OpenSubdiv, Manifold, Clipper2, meshoptimizer, mikktspace, Eigen, fmt, Material Maker. Rapier 0.22 and parry 0.17 are the physics. Other plans own: graphics (graphics-plan.md), game pipeline (game-generation-pipeline.md), libraries (engine-libraries-adoption.md), LLM harness (llm-pipeline-and-harness.md, harness-speed.md).

Inside `poly.script`, `op(id, params, inputs)` runs any registered operator (`poly_ops/script_ops.rs`; the engine offers one host function, `script::Host`, behind the global `__host`). A call builds a one-node document through the ordinary typed `AddNode` command in a fresh session, so parameter names, types, ranges and defaults are checked as everywhere else and a wrong one is refused with the operator's own reason; it then runs the operator through the same `operations::execute` the evaluator uses, with the inputs the script gave (by port name, in name order like the evaluator; an array under a port feeds a variadic port), and returns the result as data: a mesh `{points, faces}` (a solid comes back as triangles), a curve `{points, closed}`, a number `{number}`. Params are canonical units (metres, radians; the text language's degrees do not apply). Seen working: 9 more tests in `ve-modeling/tests/poly_script.rs`, 19 in all (grid result reshaped, subdivide fed a grid, a box as triangles, a boolean with a variadic list making a hole, a curve operator's points, wrong parameter refused naming the operator, unknown operator, no nested script, call limit); in the browser a 3 m block drilled by seven spheres with kernel booleans run from inside the script in the evaluator wasm (`worlds/script_ops_test.txt`, 1,442 triangles).
