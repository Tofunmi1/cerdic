## What to build (names and signatures fixed by the contract test)

1. `ArgType { Number { min: f64, max: f64 }, Text { max_len: usize }, Choice(Vec<String>), Bool }`, `ArgValue { Number(f64), Text(String), Bool(bool) }` (Clone, Debug, PartialEq), `Intent { pub name: String, pub args: BTreeMap<String, ArgValue> }`, `IntentSpec::new(name, doc)` with a builder `.arg(name, ArgType)` (all args are required; keep the order they were added), `IntentError { Duplicate(String), BadName(String) }` (thiserror), `Vocabulary`: `new()` (empty), `with_builtins()`, `register(spec) -> Result<(), IntentError>`, `get(name) -> Option<&IntentSpec>`, `describe() -> String`. A valid name is non-empty lower-case `a-z`, digits and `_`, starting with a letter, at most 40 characters.
   Builtins: `say(text: Text{max_len: 600})`, `remember(text: Text{500}, importance: Number 0..1)`, `set_fact(key: Text{80}, value: Text{200})`, `adjust_relationship(other: Text{80}, affinity: Number -1..1, trust: Number -1..1)`, `emote(name: Text{40})`.
   `describe()`: a deterministic text block for the prompt, one line per intent in registration order: `name(arg: type, ...) - doc`, with types written as `number 0..30`, `text (max 5 chars)`, `one of: calm, angry, afraid`, `true or false`.
2. `parse_reply(reply: &str, vocab: &Vocabulary) -> Parsed` with `Parsed { pub intents: Vec<Intent>, pub rejected: Vec<Rejected> }` and `Rejected { pub raw: String, pub reason: String }`. Find the **first balanced top-level JSON object** in the reply (models wrap JSON in prose or markdown fences; braces inside JSON strings, including escaped quotes, must not confuse the balancing; a cut-off object is "no JSON"). Parse it with `serde_json`; expect `{"intents": [ {"name": .., "args": {..}}, .. ]}`. Per intent: unknown name -> rejected, reason names the intent; each declared arg must be present with the right JSON type (`Number` accepts a JSON number only, `Text` a string, `Bool` a boolean, `Choice` a string that is in the list), else rejected with a reason naming the arg; numbers are **clamped** into range; text is cut to `max_len` **characters** (not bytes); arguments the spec does not declare are dropped silently. Only the **first 8 intents** are considered; the rest are rejected with a reason. No JSON object, or JSON without an `intents` array, gives no intents and one `Rejected` whose reason contains the word `JSON` (any case). Never panic on any input (fuzz it with a few thousand pseudo-random byte strings in your own test, seeded, no `rand`).
3. `PromptSections { pub persona: String, pub rules: String, pub world: Vec<String>, pub goals: Vec<String>, pub state: Vec<String>, pub memories: Vec<String>, pub conversation: Vec<(String, String)>, pub situation: String }`, `PromptBudget { pub max_chars: usize }` (Copy), `Prompt { pub text: String, pub parts: Vec<(String, usize)>, pub truncated: Vec<String>, pub over_budget: bool }`, `assemble_prompt(sections, vocab, budget) -> Prompt`.
   Output sections, in this fixed order, each as a header line `## Name` then its body, separated by one blank line: `Persona`, `Rules`, `World` (bullet lines `- ..`), `Goals` (bullets), `State` (bullets), `Memories` (numbered `1. ..` in the given order), `Conversation` (lines `speaker: text`), `Situation`, `Reply format` (a fixed instruction text asking for one JSON object `{"intents":[...]}`, mentioning the eight-intent limit and that only the listed intents exist, followed by `vocab.describe()`). **Empty sections print no header.** `parts` lists `(snake_case_name, characters_of_body)` for the sections present, in order (`persona`, `rules`, `world`, `goals`, `state`, `memories`, `conversation`, `situation`, `reply_format`).
   Budget: if the text is longer than `max_chars`, drop in this order until it fits: oldest conversation lines (keep the newest), then memories from the **end** of the list, then `world` bullets from the end, then `goals`, then `state`; record each dropped group in `truncated` as e.g. `"memories: dropped 2"`; never drop persona, rules, situation or the reply format; if those alone exceed the budget, return them and set `over_budget = true`. Deterministic: same input, same bytes.
