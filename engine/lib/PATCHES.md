# Patches to vendored code

One patch = one purpose, with the upstream reference and why it cannot live outside the fork.
Keep each change as a separate commit so it can be rebased onto a newer upstream release.

| # | Crate | Purpose | Upstream status |
|---|---|---|---|
| 5 | bevy_pbr 0.20.0 (`src/atmosphere/mod.rs`, `types.wesl`, `render_sky.wesl`) | Procedural volumetric clouds drawn by the atmosphere's sky pass: `AtmosphereSettings` gains `clouds` (cover, seed, base and thickness in metres), `cloud_look` (density, gain, steps) and `cloud_drift`. A weather map and a height profile shape the layer, a four step light march toward the sun lights it, the result is composited into the sky and in front of any geometry behind the layer. Cover 0 draws none. `ve-bevy` fills it from `scene.sky` (`clouds`, `cloud_cover`, `seed`). | Specific to our renderer; not for upstream. |
| 4 | bevy_core_pipeline 0.20.0 (`src/prepass/mod.rs`, `src/core_3d/mod.rs`), bevy_pbr 0.20.0 (`src/prepass/prepass.wesl`, `src/render/pbr_prepass.wesl`) | The prepass normal texture is `Rgba16Float` and its alpha holds the fragment depth (the raw reverse-z value, cleared to 0 for the sky). WebGL2 cannot read a depth texture (`textureLoad` has no GLSL form, and Bevy's depth copy fails there, bevy#9710), so the screen-space pass that needs depth (our ambient occlusion in `ve-bevy`, used on WebGL2 and WebGPU alike) reads it from here. | Specific to our renderer; not for upstream. |
| 3 | bevy_core_pipeline 0.20.0 (`src/blit/mod.rs`, `src/blit/blit.wesl`) | The final blit adds a linear to sRGB encode (shader def `LINEAR_TO_SRGB_OUTPUT`) when the output format is an 8-bit non-sRGB one (`Rgba8Unorm`, `Bgra8Unorm`). The WebXR layer framebuffer is such a target and WebGL2 cannot make an sRGB view of it (patch 2), so without this Bevy wrote linear values that looked dark and over saturated. Canvas windows have an sRGB format and are unaffected. | Generally correct for any non-sRGB 8-bit target; worth proposing upstream. |
| 2 | bevy_render 0.20.0 (`src/view/mod.rs`, `prepare_view_targets`) | Requests the sRGB view format for a non-sRGB main texture only when the device has `DownlevelFlags::VIEW_FORMATS`. WebGL2 lacks it, so a camera that renders to a non-sRGB target (the XR layer framebuffer) failed with a validation error when its main texture was created. | Small and generally correct; worth proposing upstream. |
| 1 | wgpu-hal 30.0.1 (`src/gles/device.rs`) | Adds `Device::texture_from_web_framebuffer`, a public constructor for `TextureInner::ExternalFramebuffer`. Upstream already renders to that variant (see `command.rs`, `queue.rs`) but nothing can create one on the web, and `texture_from_raw` is native-only. We need it to render into a WebXR layer's framebuffer. | Not proposed upstream yet. Worth upstreaming once proven on a headset. |
