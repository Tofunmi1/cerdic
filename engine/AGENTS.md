# Engine workspace: rules for contributors (human or LLM)

Run `cargo xtask check` before calling anything done. It must pass: fmt, clippy (`-D warnings`),
tests, licence policy (`cargo deny`), file size cap, crate boundaries. Fix the code; never silence a lint.

## Layout
- `crates/ve-core`   engine-agnostic core: `Name`, `Registry`. No Bevy, no platform code.
- `crates/ve-kernel` safe geometry API (`Solid`, `Mesh`) over the C++ kernel; the only `unsafe` is in `ffi.rs`.
- `crates/ve-kernel-sys` raw FFI + CMake build of `cpp/` for native and wasm.
- `crates/ve-render` render core on the vendored Bevy render crates (frame plumbing now; pipelines from M4).
- `crates/ve-xr-math` pure stereo/XR maths (asymmetric reverse-z projections, eye placement). Engine-agnostic.
- `crates/ve-xr-web` WebXR layer: JS bridge `js/xr.js` (plain values only), session lifecycle, XR frame
                     to `StereoViews`, layer framebuffer import (the only unsafe, wasm32 only).
- `crates/ve-platform-web` browser canvas window, rAF runner, pointer input (wasm32 only).
- `crates/ve-runtime` the wasm entry point the page calls (`start`, `status`); wasm32 only.
- `web/`             the page, `dist/` build output and Playwright end-to-end tests (`tests/engine.mjs`
                     scenes + goldens, `xr.mjs` and `xr-layer.mjs` against IWER, Meta's emulated Quest 3;
                     IWER needs `forceInstall` and `stereoEnabled`; real frame time needs the headset).
- `xtask`            the gates. `cargo xtask check` runs all; also `rules`, `cpp`, `parity`,
                     `web [dev]` (build the bundle) and `web-test [dev]` (build + browser test).
- `cpp/`             C++ kernel layer (Manifold, meshopt, our code). C ABI boundary only.
- `third_party/`     vendored sources (Bevy, Manifold, Clipper2, meshoptimizer), each with VENDOR.md.
- `tools/`           small helper scripts (for example the Node WASI runner used by `parity`, and
                     `serve-lan.mjs`: LAN test server for a headset, receives benchmark reports into
                     `target/reports/`; its usage is in the file header and printed when it starts).
                     `mcp/server.mjs`: test MCP server so a model (Claude Code) can drive the editor
                     page; see `docs/modeling/mcp-test-provider.md`.

Build prerequisites: Rust via `rust-toolchain.toml`, CMake, Ninja, and a wasi-sdk (set `WASI_SDK`,
default `~/.local/share/toolchains/wasi-sdk-34.0-arm64-macos`). `cargo-deny` and `cargo-nextest`
are used when installed.
- `docs/adr/`        one short decision record per big choice. Add one before changing a decision.
- `../spikes/`       throwaway experiments. Never imported from here; rewrite, do not promote.

## Rust
- Edition 2024, toolchain pinned in `rust-toolchain.toml`. Lints live in the workspace `Cargo.toml`.
- No `unwrap`/`expect`/`panic!`/`todo!`/`println!` in library code. Return typed errors (`thiserror`).
- No `#[allow]`. If a lint is truly wrong here, use `#[expect(lint, reason = "...")]` on the smallest item.
- `unsafe` is denied. FFI and platform crates opt in with `#![expect(unsafe_code, reason = "...")]`
  and every `unsafe` block carries a `// SAFETY:` comment stating the invariant.
- Parse, don't validate: turn raw strings and numbers into validated newtypes at the boundary.
- Files stay under 400 lines; split by responsibility. Public items need docs.
- Anything extensible registers in a `Registry` under a `Name`. Iteration order is by name, so
  generated output (tool schemas, snapshots) is deterministic.
- Core crates (see `ENGINE_AGNOSTIC` in `xtask/src/rules.rs`) never depend on Bevy, wgpu, winit or web crates.
- Every behaviour change ships with a test. Parsers and loaders also get a fuzz target.

## C++
- Thin kernel layer behind a C ABI; no exceptions across it (`-fno-exceptions`); explicit ownership.
- RAII only: no raw `new`/`delete`. Prefer `std::span`, `std::string_view`, `std::array`.
- `-Wall -Wextra -Werror`; config in `cpp/.clang-tidy` and `cpp/.clang-format`.
- Native test builds run under ASan and UBSan. Third-party code is vendored, pinned, licence-checked.

## Product rules (from the owner)
- All geometry and materials are generated by our own system. No retrieved or imported
  third-party models, no external 3D generators.
- GPL-licensed code stays out of the engine. Nothing is published or deployed without owner approval.
- Missing support (browser, headset, library) is ours to build.
- Commits and PRs carry no `Co-Authored-By`, "Generated with" or other tool or agent attribution.
